# PKHeX Web

A static .NET 10 Blazor WebAssembly editor on PKHeX.Core, in development and not yet the PKHeX.Web MVP. It opens raw XY/ORAS saves locally, shows the party and one box at a time, edits the species, form, nickname, language, friendship, level, experience points, nature, IVs, EVs, held item, moves, PP, PP Ups, ability and gender of an existing party member or boxed Pokémon, shows every Pokémon’s details read-only, runs Core legality analysis, and downloads a validated save. No save-processing server, upload API, persistent browser storage, analytics, or external runtime assets are used. Sprites are optional and off by default (see [Sprites](#sprites)).

## Hosting

PKHeX Web is a directory of static files. A host serves them, and the browser does everything else: there is no application server, upload API or database, and the host never receives a save. The official site is served from the root of its domain; everything below also covers a subpath such as `/PKHeX/`.

### Build

Install Microsoft's .NET 10 SDK for your platform. The verified development environment uses the machine-wide ARM64 SDK 10.0.401 and runtime 10.0.12. The Web package is pinned to 10.0.12; tests use Microsoft.Playwright 1.63.0. No repository-wide SDK pin is required (CI pins 10.0.401, because the notices list the runtime pack that SDK brings). Both projects are part of `PKHeX.slnx`. From the repository root:

```sh
dotnet publish PKHeX.Web/PKHeX.Web.csproj -c Release -o PKHeX.Web/bin/Release/publish
```

The site is `PKHeX.Web/bin/Release/publish/wwwroot`, and nothing else in the publish folder. The default Release publish trims managed assemblies but uses the stock interpreter runtime without optional native relinking or AOT; it does not need the `wasm-tools` workload. The app installs no service worker.

### Try it locally

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory PKHeX.Web/bin/Release/publish/wwwroot
```

Open `http://127.0.0.1:8080/`. Serve only the published `wwwroot`, never the repository or a directory containing your saves. Opening `index.html` from disk (`file://`) does not work: the runtime fetches its files, and browsers refuse those requests from a page on disk. Python's server sends none of the headers below, so the meta policy in `index.html` is the only protection; that is fine on your own machine, not for a public site.

### What to deploy

- Deploy the whole `wwwroot` of one publish together. Its file names under `_framework/` carry content hashes, and `dotnet.js` names the exact files of its own build, so files from two builds must never be mixed.
- Switch releases in one step: upload each release to its own directory and point the server (or a symlink) at it, or use a host whose deployments are atomic, such as Cloudflare Pages. A tab that is already open keeps the release it loaded until it is reloaded; nothing forces a reload.
- Keep the previous release's directory, or its CI artifact. Rolling back is deploying it again in the same way.
- The About panel shows the version and the source commit of the running build.

### Headers

The site needs these response headers. `wwwroot/_headers` gives them to Cloudflare Pages, and `PKHeX.Web/hosting/` has the same rules for nginx (`nginx.conf`) and Apache httpd (`apache.conf`). A Unit test fails if the snippets drift from `_headers`, and the E2E test host serves the shipped `_headers`, so the browser tests run under it.

| Header | Value | Why |
| --- | --- | --- |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'` | Only the site's own files may run or load (`'wasm-unsafe-eval'` lets the .NET runtime compile WebAssembly), there is no inline script or style, and no other site may frame the app. `index.html` carries the same policy as a meta element for hosts that cannot send headers, but a meta policy cannot carry `frame-ancestors`. |
| `Content-Security-Policy` for `LICENSE.txt`, `THIRD-PARTY-NOTICES.md` and `licenses/*` | `default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; frame-ancestors 'none'` | These open in the browser's own text viewer, which runs no script from the file. WebKit's viewer styles itself inline and Firefox asks for the site's icon; the app's policy would block both and report violations. |
| `X-Content-Type-Options` | `nosniff` | The browser uses the declared type and never guesses one. |
| `Referrer-Policy` | `no-referrer` | Links from the app (the source and license links) send no address. |
| `Cache-Control` | `public, max-age=31536000, immutable` for fingerprinted files; `no-cache` for everything else | Fingerprinted files (`_framework/*.wasm`, `*.dat`, `dotnet.*.js`, and the sprite atlas and stylesheet) never change under the same name. `index.html`, the scripts and stylesheet at the root, and the loaders `_framework/blazor.webassembly.js` and `_framework/dotnet.js` (which names every fingerprinted file) are revalidated on each visit, so a new release is picked up on the next load. |

The server must also send `.wasm` as `application/wasm`, `.js` as a JavaScript type (`text/javascript`, or `application/javascript` as nginx's standard table does), and `.dat` as a binary type such as `application/octet-stream` (neither nginx's nor Apache's standard table knows `.dat`, so both snippets declare it).

### Hosts

- **Cloudflare Pages:** upload the `wwwroot` directory as it is (Direct Upload or Wrangler). Pages reads `_headers` and does not serve it. It compresses responses itself, so the `.br`/`.gz` copies are simply unused files. The publish stays within the free plan's limits (20,000 files, 25 MiB per file), which the E2E tier checks.
- **nginx:** use `hosting/nginx.conf`. Its two `map` blocks go in the `http` block and its `server` block wherever you serve the site; set `root` to the deployed `wwwroot`. It serves the `.gz` copies with `gzip_static`; the `.br` copies need the `ngx_brotli` module (`brotli_static on`). Tested with nginx 1.30.
- **Apache httpd 2.4:** use `hosting/apache.conf` as `.htaccess` next to `index.html` (the directory needs `AllowOverride FileInfo Indexes Options`), or inside its `<Directory>` block. It needs `mod_mime`, `mod_headers` and `mod_rewrite`, and serves the `.br` or `.gz` copy the browser accepts, with the asset's own type. Tested with Apache 2.4.66.
- **GitHub Pages:** it cannot send custom headers, so only the meta policy applies: no `frame-ancestors`, no `nosniff`, and its own cache times. Deploy with the Pages Actions artifact flow. Branch publishing runs Jekyll, which drops folders starting with `_` such as `_framework`, unless the site has an empty `.nojekyll` file. A project site is served under `/<repository>/`, so it needs the subpath change below.
- **Other static hosts:** send the headers in the table above. A host that reads `_headers` may not support every feature this file uses (it relies on `! Name` to replace a value set by an earlier rule), so check the served headers.

### Under a subpath

The app loads its files relative to `<base href="/" />` in `index.html`. To serve it at `https://example.com/PKHeX/`, put the `wwwroot` contents in that folder, change the line to `<base href="/PKHeX/" />`, and delete `index.html.br` and `index.html.gz`. Those are compressed copies of the original page, and servers that use them (both snippets do) would still send `/` to browsers that accept compression, so the app would not load. In the nginx and Apache snippets, also change the not-found page to `/PKHeX/404.html`. Cloudflare Pages reads only the `_headers` at the top of the deployment, so there, move it up and start every pattern with `/PKHeX` (`/*` becomes `/PKHeX/*`, `/_framework/*.wasm` becomes `/PKHeX/_framework/*.wasm`); the nginx and Apache patterns match the end of the path and need no change. The E2E tier runs every browser test both at the root and under `/PKHeX/`.

### Missing files

`404.html` is a plain page with no script or links. Without it, Cloudflare Pages would answer every missing path with `index.html` and status 200 (its single-page-app fallback), so a missing runtime file would be handed to the loader as HTML. With it, a missing file is a 404. The snippets use it in the same way.

### Checking a deployment

Replace the address with your site's, and use one of the fingerprinted file names from the deployed `_framework/` folder:

```sh
site=https://example.com/
curl -sI "$site" | grep -iE 'content-security-policy|x-content-type-options|referrer-policy|cache-control'
curl -sI -H 'Accept-Encoding: br, gzip' "${site}_framework/PKHeX.Core.<hash>.wasm" | grep -iE 'content-type|content-encoding|cache-control'
curl -sI "${site}_framework/dotnet.js" | grep -i cache-control          # no-cache
curl -sI "${site}LICENSE.txt" | grep -i content-security-policy         # the text policy
curl -s -o /dev/null -w '%{http_code}\n' "${site}_framework/missing.wasm" # 404
```

Then open the site, open a save, and check the browser console for Content Security Policy errors.

## App shell

- **Start screen.** Before a save is open, the page states that the save is processed on this device and never uploaded, that the host still sees ordinary requests for the app's own files and may log them, which files can be opened (including the emulator prerequisites: save in game and close the emulator first; save states are not save files; loading an older save state after editing can undo the edits), and that the save and edits are not kept. The games listed come from `Services/SupportMatrix`, which is also the allowlist `SaveLoader` enforces. Once a save is open, a one-line note keeps the privacy and temporary-state message in view.
- **About.** A disclosure panel with the version, the source commit and the source repository, links to the license and notices (opened in a new tab, so the session in this one survives), the families this release opens, none of them qualified as supported yet, and the diagnostic report.
- **Startup failures.** `wwwroot/boot.js` starts Blazor itself (`autostart="false"`) and is kept to ES2015 syntax so that the old browsers it turns away can still parse it (a Unit test checks this). A browser without WebAssembly, WebAssembly SIMD or exception handling, 64-bit integer arrays or Blob downloads gets an explanation, and the runtime is never downloaded. In .NET 10 `Blazor.start()` does not settle when a download fails, so the script watches for the loader's unhandled errors that name a file under `_framework/`. Unrelated errors, such as one from a browser extension, are ignored. Once such errors have been quiet for 3 seconds without a completed start, a retry screen replaces the loading message. A download that never answers raises no error, so after 30 seconds a "still loading" hint offers a retry while loading continues.
- **Faults.** The workspace sits inside `Components/FaultBoundary`. A fault there shows a recovery screen instead of the page-wide error bar, and focus moves to its heading. It offers: return to the workspace (the open save and every applied change are kept; the unapplied draft is dropped), discard the session, or reload. Focus returns to the workspace after recovering. The session lives in `State/WorkspaceState` outside the boundary, and an apply is staged on a clone, so a fault cannot leave it half-written. No exception details are shown; the fault is recorded, redacted, for the diagnostic report and the browser console (see below), and the recovery screen offers the report too. The unsaved-changes warning is armed by the shell, so it stays in force while the recovery screen is up.
- **Diagnostics.** `Services/Diagnostics/DiagnosticLog` keeps the last 20 failures in this tab, in memory only: every refused file, every unexpected exception, a legality analysis that could not complete, a workspace fault, a sprite atlas that could not load, and refusals that mean something went wrong (a staged write or export that did not verify, a stale draft, a reset whose original no longer opens). Refusals of the user's input, such as an out-of-range level, are not recorded. Each is a `DiagnosticCode` built from the app's own names only: the outcome (such as `open.parser-fault` or `session.staged-edit-mismatch`), the Core save type a refused file was recognised as, the exception's type names and up to 12 method names from its stack, with no arguments, generic type arguments, files or line numbers. An exception's message is never read, because it can carry values from the save. The log is also the one place failures reach the browser console, in the same redacted form. Nothing is gathered for a report until the user presses "Prepare a diagnostic report" (in About, and on the recovery screen). The preview (`Components/DiagnosticPanel`, built by `DiagnosticReport`) is the whole report: the version, source commit, PKHeX.Core version, sprites, the browser's user agent, the family of the open save, and the recorded codes. It never holds the save, its file name, sizes, Pokémon or trainer names, or IDs, and nothing can add them. Copy uses the clipboard; where the browser refuses, the preview is selected to copy by hand. Download saves it as `pkhex-web-diagnostics.txt`. Nothing is ever sent.
- **Hostile names.** Stored names (trainer, box and Pokémon names) and file names are rendered as text, so markup in them is inert. For display, `Components/DisplayText` removes Unicode bidirectional controls, and a name placed inside a sentence or label (a slot label, a message, a friendship label, a download name option) is wrapped in a first-strong isolate, so a right-to-left override in a nickname cannot reverse the app's own words around it. A box or trainer name made only of such controls is treated as blank, so it gets the same label as an unset one. The nickname box still shows and edits the stored name. File names are also cleaned by `Services/FileNaming`. The page runs no inline script, and the CSP refuses one.

## Layout and accessibility

- **Panes.** Once a save is open, the workspace has a storage pane (overview, party and boxes) and an editor pane (the selected Pokémon), followed by Download and Session. On a wide screen (75rem and up) the two panes sit side by side. On a medium screen they are stacked, and while a Pokémon is open "Party and boxes" folds the storage pane away (`aria-expanded`). On a narrow screen (under 40rem) one pane is shown at a time: opening a slot shows its editor and moves focus to its heading, and "Back to party and boxes" returns to the selected slot, with focus on it (or on the storage heading when another box is shown). "Back to the selected Pokémon", at the top of the storage pane, leads back to the editor from any box, as does activating the selected slot again. A change of width that hides the element with focus moves focus to the heading of the pane still shown. A slot focused by any means becomes the grid's tab stop. The choices live in `State/WorkspaceView`; the width only decides, in CSS, which of them applies, so resizing or rotating never loses the selection, the box shown or the draft. The DOM order is the reading and tab order at every width, and nothing is sticky or overlaid, so Apply and Download are never covered.
- **Visual access.** Every colour comes from tokens at the top of `wwwroot/app.css`, with a light and a dark set. Text tokens keep at least 4.5:1 against the page background, and border, focus and selection tokens at least 3:1; `ContrastTokensTests` computes the ratios and fails on any colour written outside the tokens. Buttons, selects and fields are drawn in the token colours too, never the browser's own, whose contrast varies by engine and platform (a check in `AccessibilityBrowserTests` fails on any other colour). Every control is at least 44px tall (a checkbox or radio through its label). The page reflows at 320 CSS pixels (400% zoom) without sideways scrolling. Nothing moves, and a reduced-motion preference turns off any transition or animation added later. Statuses are words, with icons and colours only reinforcing them.
- **Validation.** A refused edit is shown on its control: it is marked `aria-invalid` and described by its fieldset's error line, which says why (`State/FieldRefusal`, `Components/EditorFields`). Typing never moves focus, and a refusal is not written to the page's status message, which is a live region and would interrupt every refused keystroke. Apply and Download use `aria-disabled` rather than `disabled`, so they stay reachable by keyboard while they cannot act. Activating one then shows and focuses a summary of every reason (`State/ActionReadiness`, `Components/ErrorSummary`, text in `Components/ValidationText`), each with a link to the control that resolves it where there is one: the refused field, the species change, the legality acknowledgement, Apply. The summary follows the reasons as they are resolved, and goes once none is left; if it had focus, focus returns to its button rather than the page body. The same list decides the buttons' state and guards what a click does.
- **Announcements.** Live regions are kept for outcomes and discrete choices: the status message, the box shown, a species or form preview and change, a rename by the nickname flag or a language change, the nature, ability, gender and move notes, and the legality verdict. Notes that follow typing (level and experience, IV and EV totals, the name, friendship, the party HP preview) are not announced; the fields and Apply are described by them (`aria-describedby`), so they are read when the control is reached. Legality announces only a final verdict (`#legality-announce`, "Legality: Valid"), never the Stale and Pending states that come and go while typing.
- **Exit dialog.** The steps of leaving a session are a native modal `<dialog>` (`Components/SessionExitPanel`): the browser keeps focus and pointer input inside it and makes the page behind it inert, so the file picker and drop zone wait until the exit ends or is cancelled. Escape cancels at every step, as "Cancel and keep this save" does, except while a download is being prepared; focus then returns to the button that opened it. The page's status message is repeated inside the dialog, where it is announced. A close the browser forces (Android back, repeated Escape) cancels too. Should the browser refuse to show it as a modal, it is shown open in place, so the exit can still be resolved. The dialog fits the screen at any width and scrolls inside itself.
- **Read-only fields.** Fields that cannot be changed (an egg's, or the handling trainer's friendship with none stored) keep full-contrast text and are marked by the control background and a dashed border, not colour alone; disabled selects and buttons have muted text and a dashed border.
- **Automated check.** `AccessibilityBrowserTests` runs axe-core (the `Deque.AxeCore.Playwright` test package; nothing is added to the app) against every WCAG 2.0–2.2 A and AA rule, at desktop and phone widths and in both colour schemes: the start screen, About with a diagnostic report, the party and boxes as a grid and as a list, the editor with an Invalid result and its findings, and the exit dialog. No rule is disabled. axe cannot judge focus order, meaningful wording or announcements; those are covered by the browser tests and, later, a screen-reader pass.

## Party and boxes

- **Views.** `Services/StorageView` reads the party and the shown box from the session's current revision, and `Components/StorageBrowser` reads them again whenever the session, its revision or the shown box changes. Nothing is cached at open, so an empty position can never show or open an earlier entity. Opening a slot (`WorkspaceState.OpenSlot`) is decided on the live save: it never replaces an unapplied draft, and an empty position or a bad egg opens nothing. Only the party and one box are read, and no legality analysis runs while browsing. Box counts, slot counts and stored box names come from Core (`BoxCount`, `BoxSlotCount`, `IBoxDetailNameRead`); a box with no stored name is shown with Core's numbered default. Party positions at or after the party count are empty, even if bytes remain there. An entity that fails Core's `PKM.Valid` (checksum or sanity flag) is shown as a bad egg, as the game and WinForms show it, with nothing read from it.
- **Positions.** `State/SlotRef` names a party position or box slot. `SaveSession.Select` opens a draft from it, reading the live save; `Components/SlotText` builds every label from the position and contents (e.g. "Box 3, slot 7 (row 2, column 1): Zigzagoon").
- **Grid and list.** `Components/SlotGrid` is a single tab stop: arrow keys move between slots, Home/End to the ends of the row, Ctrl+Home/End to the first and last slot, and Enter or Space opens one; keys held with Alt or Meta are left to the browser. `wwwroot/grid-keys.js`, loaded with the page so nothing is fetched once a save is open, stops those keys from also scrolling the page. "Show as a list" gives the same slots as a table with an Open button for each slot that can be opened. The box selector and Previous/Next wrap past either end, and the first box shown is the save's in-game current box.
- **Party.** Party members open for editing and legality analysis (analysed as party members). An edit that does not affect stats, such as the nickname, language, friendship, held item, moves, PP, ability or gender, keeps the member's stored stats, current HP and status byte for byte. An edit that does (species or form, level, experience points, nature, IVs or EVs, and a gender change that changes Meowstic's form) is handled by `State/PartyStatPolicy`: Core recalculates the stats, the status is kept, and current HP becomes the lower of the previous HP and the new maximum, so a fainted member stays fainted and its PP is not refilled. When a stat edit leaves the level and Core's calculated stats as they were for the stored member (experience points within the same level, one EV more where stats grow only every 4, or a nature changed and changed back), the stored battle state is kept byte for byte instead, so undoing an edit leaves the draft clean. The HP kept and status restored are always the stored member's, so a lower level passed through while typing never lowers HP for good. Any HP reduction is previewed before Apply (`Components/PartyHpPreview`), and the inspector labels recalculated stats as what the apply will store. A party member stored without battle stats is neither given a stat edit nor written: Core would recalculate them on write, restoring its HP and clearing its status. The HP preview follows typed edits, so it is not a live region; Apply is described by it, so it is read when Apply is reached.

## Selected Pokémon

- **Capabilities.** `State/SaveCapabilities` is worked out once per session from the concrete Core save type and the release allowlist in `Services/SupportMatrix`, which lists for each family the entity type it stores (PK6), the fields that can be drafted (species and form, nickname, language, friendship, level and experience points, nature, IVs and EVs, held item, moves, PP and PP Ups, and ability and gender, for now) and whether party drafts can be applied. A generation number alone never decides it. It also holds the session's own Core lists (`FilteredGameDataSource`: species, moves, items, balls, abilities, games and languages this save can hold); they are never assigned to Core's global `GameInfo.FilteredSources`.
- **Draft.** `State/EditorDraft` owns a private clone of the slot's entity, and only its typed edit methods change it; everything else reads a copy (`Preview`). The draft is dirty when any stored byte differs from the slot. Returning to the stored nickname restores its stored bytes, including those after the terminator, so a flag-only change never rewrites the name. An apply is staged on a clone of the save and swapped in only after it passes every check: the slot reads back byte for byte (in party format for a party member, so its stats, HP and status are compared too), the party count is unchanged, and every other party position and box slot keeps every byte (`State/SlotImages`). A refused apply leaves the session as it was. The drafted slot of every download must also read back byte for byte, with the same party count.
- **Name, language and friendship.** The name follows the desktop editor's rules (`Services/NameRules`, mirroring `PKMEditor.UpdateIsNicknamed`/`UpdateNickname`): typing a name that is not the species' name in any Generation 6 language sets the nickname flag; clearing the flag, or changing the language of a Pokémon that is not nicknamed, gives it Core's default name for its language, except that a name that is already the species' name in some language is kept, as on the desktop. The editor says which name a change gave, notes a name kept from another language (legality may report it), and warns when the game's font cannot show a character, using Core's `StringFontUtil`. Names are encoded by Core and refused, never truncated, when too long or not stored unchanged. Languages come from the session's Core list. Friendship is two labelled fields, towards the original trainer and towards the handling trainer, refused outside 0–255 rather than clamped; the second is read-only when no handling trainer is stored, and the current handler is never changed. Eggs are not edited: an egg's name must be the game's egg name and its friendship field holds the hatch counter (`Components/DraftEditor`, text in `Components/EditorText`).
- **Level, experience and nature.** Level and experience points are kept in step through Core's `Experience` growth tables, as the desktop's `PKMEditor.UpdateEXPLevel` does: a new level sets the experience points to the start of that level, re-entering the current level keeps them, returning to the stored level restores the stored ones (every keystroke is an edit, so retyping 90 passes through 9), and an experience edit moves the level. Only the experience points are written, never the party level byte of a boxed Pokémon. A level outside 1–100 or experience past the level 100 threshold is refused rather than clamped (the desktop clamps). The note under the fields gives the level's experience range and the distance to the next level. In Generation 6 the nature is stored apart from the PID, so a nature edit changes nothing else; the note and the inspector's stats table name the stat it raises and the one it lowers, in text. Natures come from the session's Core list.
- **IVs and EVs.** A table of the six stats, in the summary's order, with an IV and an EV field each, every field named by its stat and column. The limits are Core's (`MaxIV`, `MaxEV`, `EffortValues.Max510`): an IV outside 0–31 or an EV outside 0–252 is refused rather than clamped (the desktop rewrites it to the maximum, and Core's PK6 setters would clamp an IV, truncate an EV to its low byte, or write a negative IV over the egg and nickname flags stored beside it). An EV edit that raises the total above 510 is refused; one that lowers it is always accepted, so a stored total over the limit can be brought down a stat at a time. Only the edited stat's bits are written. The notes under the table give the IV total and the Hidden Power type the IVs give, and the EV total, how many remain and Core's grading of it (508 uses every effective EV; 510 is the most).
- **Held item and moves.** The held item is chosen from Core's list of items the game lets a Pokémon hold, or none; a move from Core's list of the game's moves (`FilteredGameDataSource`), or none. The move list says nothing about what the Pokémon can learn, and the editor says so: legality analysis checks it. A table has a row per move slot with the move, its PP, its PP Ups (0–3) and its PP with them (`GetMovePP`). A move change sets that slot's PP as the desktop does (`MoveChoice.HealPP`): the new move gets full PP for the PP Ups it keeps, a move PP Ups cannot be used on (Sketch) has them removed, and an emptied slot has no PP or PP Ups; changing back to the stored move restores its stored PP and PP Ups. The PP Ups a new move keeps are the slot's last count on a move that can take them, so typing a name into a move box, which picks a move per keystroke ("sky" passes Sketch on the way to Sky Attack), does not lose them; a stored count above 3 is never carried. A PP Ups change refills the PP, and changing back restores the stored PP. A note under the table says what the last move or PP Ups change did. PP is refused outside 0 to the move's PP (and above 255, the byte it is stored in) and never clamped, and an empty slot has no PP to edit. Only the edited slot is written: the others keep their place, and an empty slot is not filled from the next one (the desktop's `FixMoves` would). A value stored outside the lists, or PP or PP Ups stored above the maximum, is shown as stored and kept until changed; a move or item Core knows but this game does not list (an Omega Ruby move on a Pokémon traded into X) is named as the inspector names it. The move and item boxes (`Components/ChoiceSelect`) render again only when their own value changes, and every box's value is set on the select rather than an option's `selected` attribute, which Firefox ignores once the user has chosen.
- **Ability and gender.** The ability box lists the species' and form's three ability slots from Core's personal data (`FilteredGameDataSource.GetAbilityList`), named as the desktop names them ("Pickup (1)", "Gluttony (2)", "Quick Feet (H)"). Each choice is a slot, so two slots with the same ability stay apart, and choosing one writes the ability and its slot number together, as the desktop does (Core's `SetAbilityIndex`, which for Generation 6 changes no PID). A stored ability and slot number that do not name one of the slots together are shown as stored and kept until a slot is chosen. The note says that whether the Pokémon could have its hidden ability depends on how it was met, which legality analysis checks. The gender box offers only the genders the species can have (`State/GenderRule`, from the personal data's gender ratio): male and female, or the single gender of an always-male, always-female or genderless species, which also corrects a wrong stored value, as the desktop's gender toggle does; a value the species cannot have is shown as stored. In Generation 6 the gender is stored on its own, so a gender change writes nothing else, and a Pokémon from Generations 3–5, whose gender legality checks against its PID, is not given a new PID. Meowstic's form is its gender: changing its gender changes its form too, through Core's `ChangeSpeciesForm`, as the desktop's `ClickGender` does, so the ability keeps its slot but is taken from the new form (Prankster becomes Competitive) and the experience points become the start of the level; a note says what changed, and changing back gives back the experience points, ability and slot number it had before, unless one of them has been edited since (see Species and form). Only a species with two genders has gendered forms, as `ClickGender` checks first, so Unown's F and M forms, whose names read as gender symbols, are never changed.
- **Species and form.** The species box lists Core's species for the save (without "none", which would empty the slot) and the form box the species' forms from Core's form list for the generation, shown only when the save's personal data gives the species a form choice, as the desktop's form box is; X and Y saves therefore get no form box for Omega Ruby/Alpha Sapphire-only forms such as cosplay Pikachu or Primal Kyogre. Forms that exist only in battle (Megas, Primal forms, Castform's weather forms, …) are marked "(battle only)". A choice is not made at once: the editor first previews it, listing every dependent field Core's `ChangeSpeciesForm` reports changed (form, experience points and level, ability, gender, PID, name) with its values before and after, the stats that change, a party member's current HP, and whether legality analysis will report the form, and the draft changes only when the preview is confirmed. While a preview is shown, Apply and Download wait until it is made or dropped, since neither would carry the choice the boxes show. The change itself is Core's `ChangeSpeciesForm`, the helper the desktop's `UpdateSpecies`/`UpdateForm` use: the experience points become the start of the level they give on the new growth curve, the ability keeps its slot, the gender is made one the species can have (and follows Meowstic's gendered form), a Pokémon that is not nicknamed takes the new species' name, and the PID is never changed. Moves, IVs, EVs, nature, held item and form timers (Furfrou's trim, Hoopa's unbound days) are kept as stored; legality analysis reports what the new species cannot have. Changing back to the species and form a run of changes started from gives back the values the run changed, unless one of them has been edited since, so changing and changing back leaves the draft clean; a Meowstic gender edit is part of the same run.
- **Inspector.** `Services/EntityInspection` reads the drafted entity, unapplied edits included, through typed Core members only (no reflection, so it is safe under trimming), and `Components/EntityInspector` shows it read-only in five sections: Identity, Stats, Moves, Origin and trainer, and Advanced (PID, encryption constant, ribbon count, Pokérus, markings, checksum). Names come from Core's strings. A value Core cannot name is shown as "Unknown (stored value N)", and one outside this game's lists keeps Core's name with "(not available in this game)". A party member's stats, HP and status are shown as stored; a boxed Pokémon stores none, so its stats are calculated by Core without writing them to the entity. Stored names are rendered as text.
- **Previous and Next Pokémon.** Under the editor's position, `#draft-prev` and `#draft-next` open the Pokémon before or after the selected one without going back to the party and boxes: every party member, then every box slot in Core's order (`StorageView.Neighbour`), skipping empty positions and bad eggs (eggs open, read-only), wrapping from the last box to the party. The box shown follows the draft, and the grid's tab stop moves to its slot, so the return action on a phone lands there. Focus stays on the button. As when a slot is opened, a draft with unapplied or refused changes is never replaced: the buttons stay focusable (`aria-disabled`) and, when activated, show and focus `#step-summary` with a link to Apply changes or to the refused field. A pending species or form preview holds them back too (`ActionReadiness.ForStep`).
- **Searching moves and items.** Above each move box and the held item box is a search field (`Components/ChoiceSearch`), with a visible "Search" label (the rest of its name, such as "moves for Move 2", is visually hidden), that narrows the box to the entries whose names contain what is typed, ignoring case, accents and punctuation (`State/ChoiceFilter`: "poke ball" finds "Poké Ball", "uturn" finds "U-turn"). Typing only narrows the list: the drafted value and "(None)" are always kept, so no keystroke changes the draft, and a choice is still made in the box. A note under the field, read with it rather than announced, says how many entries match. The search is cleared when another draft opens. Options are keyed by value, so the browser keeps the drafted option selected while the list around it changes.

## Legality

- **Service.** `Services/LegalityService` runs Core's `LegalityAnalysis` on a copy of the draft, with the save's personal table and the slot's storage type (a party member is analysed as one). The draft and the save are never changed. The verdict, the findings and both reports are Core's: problems are the lines of Core's short report, in its order, followed by the checks Core judges suspicious, each with Core's severity. Core's active trainer is set to the session's save for each analysis and cleared afterwards, as the desktop editor sets it when a save is loaded: some checks, such as the current-handler state, compare the entity with the save's trainer and run only then. Core catches exceptions inside the analysis itself and reports the entity as not parsed; that, or an exception outside Core's guard (formatting the reports), is *Unavailable*, never legal. The cause is recorded, redacted, for the diagnostic report and the browser console: the exception's types and frames, or `LegalityNotParsedException` when Core caught it.
- **When it runs.** `State/DraftLegality` analyses the open draft once it has been unchanged for 300 ms: after opening a slot, after each accepted edit, and after an apply or a cancel reopens the slot. "Analyze now" runs it at once. Only the selected entity is analysed, never the whole save, and nothing runs while browsing.
- **States.** Not analyzed, Pending, Stale, Valid, Invalid and Unavailable are separate, each a word with a decorative icon. Every result is tagged with the draft and its edit count (`LegalityTag`), and the status is worked out from the live draft, so an accepted edit makes the result *Stale* at once. A run marks the panel busy (only while it is still for the draft as it is now) and waits for one paint before calling Core, which is synchronous on the page's only thread, so *Pending* is visible first. An edit, a new draft or a closed session in that moment supersedes the run, and Core is not called. A refused edit is *Stale* until it is corrected or cancelled. "Analyze now" is disabled only while an analysis runs, so it also skips the idle delay.
- **Findings and reports.** Only a result that matches the draft as it is now lists findings, so nothing out of date shows while typing. A finding links to the inspector section that shows the value it is about, where one does (`Services/LegalitySections`; relearn moves, memories and similar have no link). Core's short and verbose reports sit in a collapsed "Full report" disclosure. The panel names the PKHeX.Core version and source commit that analysed the entity, says that legality is diagnostic, and says that a result is not an online acceptance guarantee.
- **Acknowledgements.** Legality findings are warnings, not a ban on saving an illegal Pokémon, but they are never passed over silently. Apply waits until the draft as it is now has a result (`DraftLegality.Gate`; "Apply is available once legality has analysed the draft as it is now"). A Valid result applies at once. An Invalid or Unavailable one needs its checkbox ticked first, and any accepted edit unticks it, because the new result has to be acknowledged afresh. The session records each slot whose latest apply was acknowledged this way (`SaveSession.FlaggedChanges`; a later Valid apply of the slot removes it). A download that contains any of them lists them by position and needs its own acknowledgement, which belongs to the session's current revision, so any later apply withdraws it (`SaveSession.ExportNeedsAcknowledgement`, checked again by `SaveExporter`). Pokémon that were already illegal when the file was opened, and were not changed, are downloaded without asking. The exit panel's Apply draft and Download steps show the same checkboxes.
- **Cost.** The `Perf` tier times every PK6 in Core's legality test fixtures in all three engines (`legality-timing.md`). On the development machine, a warm analysis takes at most about 60 ms; the first one in a page, which loads Core's legality tables, takes about 300–400 ms.

## Downloading and leaving a session

- **Change and download state.** Three separate indicators: the draft ("Unapplied draft"), the session ("Edited in memory" once any change is applied, and it stays so after a download, because the session still differs from the opened file), and the download (`SaveSession.ExportStatus`: no changes, not downloaded yet, download started for the current changes, or changed since the last download). A no-op apply is not a change. The browser reports only that a download started, so no text says the file was saved; every download asks the user to verify the file.
- **Download.** `Services/SaveExporter` writes a clone of the working save and reopens it through the loader before anything is handed to the browser; a failure produces no download and leaves the session as it was. The same revision can be downloaded again.
- **File name.** Once changes are applied, the suggested name is the opened name with `-modified-` and the local date and time of the download before the extension (`main` becomes `main-modified-2026-10-01-143205`), so an edited download cannot be mistaken for the original. A reopened edited download gets a new stamp in place of its old one. The original name can be chosen instead, and is the default while the session is unchanged. Whenever the chosen name is not exactly `main`, a note says to rename the file to `main` before restoring it with a save manager or in an emulator. The time is the browser's, in its time zone; browsers may still adjust the name when saving.
- **Leaving a session.** Opening another file, choosing Close save or choosing Reset to original on a session with changes starts an exit (`State/WorkspaceState.Exit`) that resolves, in order: an unapplied draft (apply it or discard it), then changes not covered by a download (download them, or discard the session, which is the explicitly destructive choice), then, once the current revision has been downloaded, "Continue; I have checked my export". Cancel keeps the session, draft and editor at every step. The step is worked out from the live session each time, so a change applied after the download takes the exit back to the download step. A session with nothing to lose is replaced or closed at once. Refused files never touch the session or a waiting file. The steps are shown in a modal dialog (see [Layout and accessibility](#layout-and-accessibility)); Escape cancels. Focus moves to the dialog's heading at each step, and back to the page (the button that started a cancelled close, reset or discard, otherwise the open heading) when the dialog goes.
- **Reset to original.** Offered once changes are applied. It parses a fresh copy of the bytes the session was opened from, under the same name, before asking anything (XY and ORAS have no edition or language choice to repeat), and a parse failure keeps the session as it was. The fresh session waits as the exit's candidate, so the draft, the changes and a download are resolved as for a replace. Completing it clears the draft, every applied change, the flagged changes and the download status.
- **Discard session.** The explicitly destructive way out: one confirmation that names what is lost (the unapplied draft, changes not downloaded, or a download that has not been checked), with no draft or download step, then the start screen. Close save remains the way that offers to apply and download first. A session with nothing to lose closes at once.
- **Page lifecycle.** `wwwroot/lifecycle.js` warns before the page is left only while leaving would lose work (best effort: mobile browsers can end a tab without any event). A page that enters the back-forward cache is hidden as it goes in, and a restored copy reloads at once without warning again, so it never shows or accepts input for the old session; a reload or a back navigation always starts empty. Nothing is stored in the browser.

## Sprites

A default publish contains no images: slots are shown as text, and the About panel says so. Whether the PKHeX desktop's sprite images may be redistributed on a public static host is a decision for the maintainers, so the atlas is published only on request:

```sh
dotnet publish PKHeX.Web/PKHeX.Web.csproj -c Release -p:PKHeXWebSprites=true -o PKHeX.Web/bin/Release/publish-sprites
```

- **Generator.** The publish runs `PKHeX.Web.SpriteAtlas` (a build tool in this repository, never part of the site). It reads the images PKHeX.Drawing.PokeSprite embeds through that project's `Properties/Resources.resx`, and packs the ones an X/Y or Omega Ruby/Alpha Sapphire entity can use into `sprites/pokemon.{hash}.png`: 1,838 images of 68x56, about 1.2 MiB. It also writes `sprites/sprites.{hash}.css` (one class per cell), `sprites/manifest.json` (the names of those two, and which image is in which cell) and `sprites/sources.json` (each image's source file and SHA-256), with `.br`/`.gz` copies of the text files. The atlas and stylesheet are named by a hash of their content because adding one image moves every later cell: a browser can never combine files from two deployments, and one holding an older manifest asks for files that no longer exist and shows text. Its PNG codec is its own, so the build needs no image library, and the output is identical for identical sources; the Unit tier checks that, and that every cell holds its source's pixels unchanged.
- **Choosing a sprite.** `Services/Sprites/SpriteKeys` chooses images the way the desktop does for these saves, using the desktop's own naming code (`PKHeX.Drawing.PokeSprite/Util/SpriteName.cs`, compiled into both the app and the generator): the sprite for the species, form, gender and shininess, then the species' default sprite with the unknown mark for a form without one. Eggs show their species with the egg icon, and shiny entities the shiny star, as the desktop draws them. Held-item icons are not drawn. The generator packs exactly the images this can choose, and a Unit test checks that every species, form, gender and shininess of Generation 6 has its own sprite. Entities no X/Y or Omega Ruby/Alpha Sapphire save can validly hold, such as a form beyond the species' range or a species above 721, show the species' default sprite with the unknown mark (or the mark alone) where the desktop may still find a later game's image.
- **Privacy.** A request for one species' image after a save is opened would tell the host what the save holds. The app therefore loads the manifest, the stylesheet and the whole atlas before it renders (`Program.cs`), so a save cannot be chosen until the atlas is resident, and the requests are the same for every save. Every sprite is an `img` of that same preloaded atlas, shifted to its cell by the stylesheet's class, so drawing one makes no request. If any part fails to load, or has not loaded within 20 seconds (the app waits for it before rendering), no sprite is ever drawn and slots stay text.
- **Accessibility.** Sprites are decorative: they are hidden from assistive technology and have empty alternative text. Each slot keeps its visible text and its accessible name, and hovering shows the same label.

`THIRD-PARTY-NOTICES.md` gives the images' provenance and attribution. A `dotnet run` development host shows text only: the atlas is added at publish.

## Build provenance and notices

The About panel shows the Web version (the repository `Version`) and the git commit the build was made from, which also identifies the Core revision. Both are embedded at build time as assembly metadata by the `AddBuildProvenance` target in `PKHeX.Web.csproj`, using the SDK's built-in git query, so no `git` executable is needed. The commit is the checked-out one; uncommitted changes are not reflected. It is recorded only when the git repository is this repository, so a build from a source archive, or from a copy inside another repository, records `unknown`; pass `-p:PKHeXSourceCommit=<sha>` to record it explicitly.

The publish output includes `LICENSE.txt`, `THIRD-PARTY-NOTICES.md` (every package the Web build restores, with its version and license, split into published, removed by trimming and build-only) and the upstream .NET notices under `licenses/`. Serve them together with the rest of `wwwroot`. The E2E tier fails if the restore graph changes without a matching update to `THIRD-PARTY-NOTICES.md`, or if the publish contains a package file the notices do not list as published. The runtime pack version comes from the installed SDK, so a different SDK patch needs a notices update; those checks are therefore in the opt-in E2E tier, which CI runs on the pinned SDK, rather than in Unit.

## Reproduce tests

Private files are supplied through environment variables; never copy them into source or `wwwroot`. Use absolute paths. The two fixture variables must refer to valid, decrypted real saves, not synthetic substitutes. Test downloads live in temporary Playwright storage and are removed when the browser context closes. Screenshots and traces are not recorded.

```sh
export DOTNET_CLI_TELEMETRY_OPTOUT=1
export PKHEX_XY_SAVE='/absolute/private/path/to/xy-save'
export PKHEX_ORAS_SAVE='/absolute/private/path/to/oras-save'
export PKHEX_WEB_TEST_TIERS='E2E,RealSave'
export PKHEX_WEB_PUBLISHED="$PWD/PKHeX.Web/bin/Release/publish/wwwroot"
export PKHEX_WEB_PUBLISHED_SPRITES="$PWD/PKHeX.Web/bin/Release/publish-sprites/wwwroot"   # the E2E tier also tests a publish made with sprites
export PKHEX_PROOF_EVIDENCE="$(mktemp -d -t pkhex-proof-evidence)"

dotnet build Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release
```

Install the browsers matching the pinned Playwright package. If PowerShell is installed, use the generated `playwright.ps1 install chromium firefox webkit` script in the test output directory. On macOS ARM64, the bundled equivalent is:

```sh
Tests/PKHeX.Web.Tests/bin/Release/net10.0/.playwright/node/darwin-arm64/node \
  Tests/PKHeX.Web.Tests/bin/Release/net10.0/.playwright/package/cli.js \
  install chromium firefox webkit
```

Tests are split into tiers by `Category`. A run without `--filter`, including `dotnet test PKHeX.slnx`, executes only `Unit`, so desktop contributors without browsers or private saves still get a clean run. Passing any `--filter` or `--settings` replaces that default (and a filter on the solution applies to every project), so select tiers explicitly:

```sh
dotnet test Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release --no-build                                                          # Unit (synthetic saves, no setup)
PKHEX_WEB_TEST_TIERS=E2E dotnet test Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release --no-build --filter Category=E2E             # published app + Playwright
PKHEX_WEB_TEST_TIERS=RealSave dotnet test Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release --no-build --filter Category=RealSave   # also needs the private saves and the publish
PKHEX_WEB_TEST_TIERS=E2E,RealSave dotnet test Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release --no-build --filter "Category=Unit|Category=E2E|Category=RealSave"
PKHEX_WEB_TEST_TIERS=Perf PKHEX_WEB_PERF_REPORT="$(mktemp -d)" dotnet test Tests/PKHeX.Web.Tests/PKHeX.Web.Tests.csproj -c Release --no-build --filter Category=Perf   # boot baseline and legality timing, also need the publish
```

Set `PLAYWRIGHT_BROWSERS_PATH` consistently for installation and testing if you want a custom browser cache location. It is separate from the machine-wide SDK.

`E2E`, `RealSave` and `Perf` are also opt-in: their tests run only when the tier is named in `PKHEX_WEB_TEST_TIERS` (separated by commas, semicolons or spaces; case-insensitive), and are skipped otherwise. This keeps runners that ignore the project's default filter to `Unit`: `vstest.console` run directly on the built assembly (as Azure Pipelines' VsTest task does) runs the Unit tests and skips the others instead of failing them. An opted-in tier still fails, rather than skips, when its other environment variables are missing; `RealSave` needs `PKHEX_WEB_PUBLISHED` as well as the saves, because its browser test uses the published app. A filter for a tier that is not opted in skips every test and reports success, so name the tier in both places; `PKHeX.Web/tools/trx-all-executed.sh <results.trx>` fails a run in which any test was not executed. CI runs `Unit`, `E2E` and `Perf`; `RealSave` is for local runs with private saves.

Browser tests share one fixture that starts a loopback-only static host for the supplied published files and checks every boot, at the root and under `/PKHeX/`: only published files are requested and none fails; each response carries the expected MIME type, `nosniff`, the Content-Security-Policy header and `Referrer-Policy`, and the page reports no CSP violations. The host sends the headers the published `_headers` gives each path, applying its rules as Cloudflare Pages does (`HostHeaders`), never serves `_headers` itself, and answers a missing file with `404.html` and status 404. The expected values are written out separately in the tests (`ExpectedHeaders`), so a wrong rule in `_headers` fails the boot checks rather than agreeing with itself. `DeploymentHeadersTests` checks the cache rule, policy and headers that `_headers`, `hosting/nginx.conf` and `hosting/apache.conf` give every file of the default and sprite publishes, that a missing file is a 404 and never the app, and that the license opens in each engine's text viewer without a policy violation. Each test ends by checking that nothing reached the network after boot, that nothing was persisted in the browser, and that no CSP violation occurred, including across reloads. The `/PKHeX/` cases change only the served HTML base href to reproduce a subpath deployment; all application binaries are identical. The host has no upload or save-processing endpoint. An absent fixture variable or missing usable entity fails rather than silently skipping the real-save proof.

`JourneyBrowserTests` runs the whole journey in one session, in every engine and at both paths (XY at the root, ORAS under `/PKHeX/`). It opens a save through the picker and replaces it with a dropped one. It downloads the dropped save unchanged, then edits one field of every editor group across a boxed Pokémon and a party member, compares each draft's legality with native Core, and applies both. The edited download must equal native Core's output for the same edits byte for byte, and must reopen natively holding both Pokémon exactly as planned, with nothing changed outside the two slots and the checksum footer. Reopened in the app, every edited control must hold its value, legality must agree with native Core again, and a no-op download must give back the same file. The edits and their native recipes live in `JourneyPlan`; `JourneyPlanTests` fails if they stop reaching every fieldset of the editor, and the journey fails if a step would leave its control as it was. The journey's privacy trace checks that the page address never changed and that no typed or saved value reached the console: the nickname, the file name, the trainer and the box names. It also checks that no dialog appeared, that nothing reached the network or browser storage after boot, and that the files given were not changed. A second fresh visit that opens another save and Pokémon must make exactly the same requests. A keyboard-only run uses only Tab, Shift+Tab, Enter, Space and typing (Option is added in WebKit, as in Safari). It opens a file through the file input, opens a party member and a boxed Pokémon from their grids, edits text fields, ticks the acknowledgements, applies, and downloads output equal to native Core's, and it fails if a pointer press reaches the page.

Real-save tests select the first occupied, checksum-valid, writable boxed PK6 in box/slot order and fail if none exists. A second round trip edits the first party member and fails if the save has no party. A third edits friendship towards each stored trainer on the first writable boxed Pokémon that is not an egg. A fourth steps the level and changes the nature of that Pokémon and steps the level of the first party member, a fifth steps an IV and an EV of that Pokémon and an IV of the first party member, a sixth changes a move and the held item of that Pokémon and steps the PP of the first party member, a seventh steps the ability slot of that Pokémon and changes the gender of the first party member that can be male or female, an eighth changes the species of that Pokémon and of the first party member that is not an egg, and a ninth runs the whole journey of `JourneyBrowserTests` on the save (`JourneyPlan` picks the first party member that can be edited in every group, and fails if there is none); each compares with native Core and the party-stat policy. Outside the edited slots and the Gen 6 block-checksum footer, the edited export must be byte-identical to the no-op export. No entity is injected into the real fixture.

Evidence JSON contains only family, slot kind (box) or the journey with the number of fieldsets it edited, browser/version, hosting path, timings, and pass flags. It contains no file paths, names, trainer identifiers, entity contents, or save hashes. Native reference outputs and browser downloads are compared in memory; private bytes are never included in assertion messages.

## Boot baseline

The `Perf` tier measures how long the published app takes to become usable (WEB-PERF-001) and how long the selected-entity legality analysis takes (WEB-PERF-004), and writes `boot-baseline.md`/`.json` and `legality-timing.md`/`.json` to `PKHEX_WEB_PERF_REPORT`. It records numbers only and has no pass/fail threshold; it fails only when a boot cannot be measured (the file input never became usable within 60 seconds, a page error, or a request for anything other than a published file), or when an analysis cannot be measured or shows a verdict other than native Core's. `PKHEX_WEB_PERF_RUNS` sets the number of measured boots per configuration (default 5), after one unrecorded boot.

- Each sample uses a new browser profile. The cold boot starts a new browser process on the empty profile; the warm boot closes that browser and relaunches it on the same profile, like a returning visit, so only what the browser stored in the profile (its HTTP cache) carries over.
- "Shell ready" is the time from navigation start until the file input exists and is enabled, recorded in the page by a mutation observer.
- Chromium is measured on the 20 Mbps / 50 ms profile that `PKHeX.Web.md` states its targets for (≤5 s cold, ≤2 s cached; engineering targets, not claims), throttled through the DevTools protocol, which adds the latency to each request rather than emulating TCP round trips. Playwright cannot throttle Firefox or WebKit, so all three engines are also measured on unthrottled loopback, which shows the startup cost without the network.
- The loopback host runs in a deployment-caching mode: it serves the precompressed `.br`/`.gz` file the browser accepts, sends `ETag`s and answers revalidations with 304, and sends the `Cache-Control` the shipped `_headers` gives each file (immutable for fingerprinted files, `no-cache` for everything else; the browser tests' default mode leaves it out). Playwright's WebKit does not accept Brotli from the plain-HTTP loopback host, so its rows are served as gzip, which overstates what an HTTPS deployment transfers; the report's boot-set table gives both sizes.
- The report lists the files a cold boot downloads with their raw, Brotli and gzip sizes, the raw size of each group of data embedded in PKHeX.Core (every boot downloads all of it inside the assembly) and its share of the published file, and flags a warm boot that reused nothing from the cache, since that row then measures a second download. Playwright's WebKit did so in every local run; the cause has not been established, and it is not evidence about Safari.

Numbers from a shared CI runner vary between runs and are not the reference desktop the targets name; compare runs on the same machine.

## Continuous integration

`.github/workflows/web.yml` runs for pull requests, and for pushes to `master` and `web/main`, that touch Core, Web, WinForms, the Drawing projects or the tests. The workflow has read-only repository permissions, no secrets, and actions pinned to commit SHAs.

- **`changes`** decides what a pull request needs from the paths it changes (`PKHeX.Web/tools/ci-changes.sh`): `web` when the published app can differ (Core, Web, the sprite generator and PokeSprite, the Web tests, `Directory.Build.props`, `LICENSE`, `.gitattributes`, the workflow), and `sprites` when the publish with sprites can. A WinForms-, Drawing- or Core-test-only pull request therefore runs only the Core tests and the `Unit` tier on Linux, plus `azure-parity`. Pushes to `master` and `web/main` always run everything, so anything the lists miss is caught before it ships; if the diff cannot be read, everything runs.
- **`web`** runs on Linux, inside Microsoft's Playwright image for the test project's Playwright version (`mcr.microsoft.com/playwright/dotnet`, pinned by digest). The image carries the three browsers, their system libraries and the SDK; installing those libraries on the stock runner took over 14 minutes whenever the Ubuntu mirror was slow. It pins SDK 10.0.401 with a `global.json` written outside the checkout, because the notices list the runtime pack version that SDK brings, and fails if the image brings any other SDK or a Playwright version other than the test project's. It always runs the Core tests and the Web `Unit` tier. When the app can differ, it also publishes Release with trim-analysis warnings logged, checks them against the baseline, and uploads the published `wwwroot`. On pushes to `master` and `web/main` only, it then runs the `Perf` tier, with a check that every test was executed: the tier has no threshold, so pull requests skip its two minutes. At the end it uploads the test results and reports: normalised trim warnings, the `dotnet list package --include-transitive` inventory, a size report, the boot baseline and the legality timing, the last three also shown in the run summary.
- **`e2e (chromium|firefox|webkit)`** runs the `E2E` tier, one engine per job (`PKHEX_WEB_ENGINES`), in parallel, in the same image and only when the app can differ. Each job publishes for itself rather than waiting for `web`. When the sprite inputs changed (always on pushes), it also builds the publish with sprites: tested, its size shown in the run summary, but never uploaded. Otherwise it leaves out the tests that need it with `--filter "Needs!=SpritePublish"`. A sprite test missing that trait still fails rather than passes, because the sprite publish's variable is unset. Tests that take no engine (the publish checks) run in every job. A check then requires every selected E2E test to have been executed.

`RealSave` never runs in CI. Locally, `PKHEX_WEB_ENGINES=firefox` (comma-separated; all three when unset) limits the browser tiers to the named engines.

The `azure-parity` job repeats upstream's Azure Pipelines build on Windows, so that the Web projects cannot break it unnoticed. It runs on `windows-2022`, whose Visual Studio 2022 17.14 and SDK match Azure's `windows-2025` agent (GitHub's `windows-2025` now has Visual Studio 2026), and uses GitVersion 5.x for `/p:Version`, a `nuget.exe` restore of `PKHeX.slnx` and a Release build with x86 Visual Studio MSBuild. There is deliberately no SDK pin: Visual Studio MSBuild uses the newest SDK its version supports on the image, as upstream does. It then runs `vstest.console` over `**\bin\Release\**\*Tests.dll` without `PKHEX_WEB_TEST_TIERS`, and `PKHeX.Web/tools/trx-check-opt-in-skips.ps1` requires the Core and Web Unit tests to pass and only the opt-in tiers to be skipped. The run summary lists the toolchain it used.

The E2E test `PublishesOnlyStaticDeployableFiles` keeps the publish deployable as static files: at most 20,000 files, none over 25 MiB (the Cloudflare Pages limits), only the expected asset types in their expected folders (runtime files in `_framework/`, upstream notices in `licenses/`, the app shell, scripts and styles, `404.html`, `_headers`, the license and the notices at the root; so no source maps, symbols, sources or stray data files), and every precompressed `.br`/`.gz` file next to the asset it compresses. `SpritePublishAddsOnlyTheAtlasFiles` applies the same rules to the publish with sprites, where `sprites/` may hold only the four generated files and their precompressed copies, and the default publish must have no `sprites/` at all. `PKHeX.Web/tools/size-report.sh <wwwroot>` prints the size report locally.

Blazor hides trim-analysis warnings in a normal publish. `PKHeX.Web/tools/trim-warnings.sh` publishes again with them enabled (or, with `--log <file>`, reads the log of a publish that had them enabled, as CI does) and compares them with `PKHeX.Web/trim-warnings.baseline.txt`, ignoring source locations and the ordinals in compiler-generated names. Any difference fails: justify a new warning, or drop a fixed one, then run the script with `--update` and commit the baseline.

## Boundaries

- Core chooses the format, parses entities, analyzes legality, writes slots and serializes saves. No Core source or public API changes are required.
- Apply edits a temporary working copy; Download does not confirm filesystem persistence. A changed session remains visibly edited after downloading.
- Replacing, closing or resetting a changed session requires a download followed by an explicit confirmation, or an explicit discard; Cancel is always available.
- An Invalid or Unavailable legality result is applied, and downloaded, only after an explicit acknowledgement; nothing is repaired.
- An empty box is not an invitation to generate a Pokémon. The app does not import entities, legalize them, or manipulate dex/records.
- Input and working-save integrity are checked, but console acceptance and physical Safari/iOS behavior are not established by these tests.
- Playwright WebKit is engine coverage, not a claim of physical-device qualification.

See the root `PKHeX.Web.WasmProof.md` for the actual recorded evidence and limitations.
